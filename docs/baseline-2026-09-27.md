## What the numbers show

**Workers now use their tools.** The single worker made 12 model calls. A worker
that writes a file, inspects its diff, and runs a check cannot do so in one call,
so this is direct evidence that the 2026-09-22 fix holds on a real objective. The
comparison is stark: in run `a892546081ce` (2026-09-20) both workers made exactly
one call each, produced an empty workspace diff, and failed validation twice.

This also settles a planned change. Two-phase worker finalization — splitting the
tool phase from a tool-free structured emit — was on the roadmap conditional on
this measurement showing single-call workers or turn-budget losses. It showed
neither, so that work is not warranted and has been dropped.

**Orchestration overhead fell from 90% to 44% of calls.** The last instrumented
run spent 19 Manager calls against 2 worker calls. This one spent 12 against 15.

That said, this is not a controlled comparison and should not be read as one. The
Manager model changed (`kimi-k3` → `deepseek-v4.1-flash`), the objective differs,
and — most importantly — the earlier run *failed* while this one succeeded, so
some of its Manager calls were spent diagnosing a soft-locked task that no longer
occurs. The bounded read path plausibly contributes, but this run does not isolate
its effect.

**Manager tokens remain the largest line item.** 104,806 tokens over 12 calls is
~8.7k per call, two thirds of total spend, for a single-task objective. The
roadmap target is ≤6 Manager calls median for work of this size; 12 is twice that.
Reducing Manager turns is the open cost problem.

## Limitations

- One run. It establishes that the path works, not how reliably.
- Single task, no dependency graph, so accepted-only dependency unlocking was not
  exercised live.
- Python only, which is the entire sandbox command surface today.
- The `developer_sandbox` candidate succeeded first try; the recovery routes
  (`REVISE`, `REPLACE`, `ESCALATE`, `REPLAN`) were not exercised in this run and
  remain covered only by offline tests and the 2026-09-20 failures.
